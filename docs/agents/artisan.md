# Artisan Forms and Wishlist

Feature reference for Keebdex agents; project-wide rules live in [AGENTS.md](../../AGENTS.md).

Artisan rules that are not part of submissions or edit suggestions: sculpt renames, the colorway stem field, and the Wishlist Image builder.

- **Sculpt renames**: Renaming a sculpt (`app/components/artisan/modal/SculptForm.vue`) always changes its slug, through any path (the form, an approved edit suggestion, a revert). Colorways reference sculpts by `maker_sculpt_id` (on update cascade), and `update_maker_sculpt_id()` takes a cascaded key's maker and slug on colorways, so they follow the sculpt in the same statement; a rename writes one sculpt revision and none for the colorways (see `docs/agents/revision-history.md`). catalog-sync matches sculpts by slug, so `keep_source_slug()` saves the old slug of a `gdoc`/`scraper` sculpt to `source_slug` on its first rename and the sync matches on `coalesce(source_slug, sculpt_id)`; colorway images keep their old path (`update_maker_sculpt_id()` in `20260101000700_baseline_triggers`, the column and `keep_source_slug()` in `20261021000100_page_renames`, the protected fields in `20261017000000_edit_suggestions`). A suggested rename suggests the new `sculpt_id` too (`slugKeys`, see `docs/agents/edit-suggestions.md`); `maker_sculpt_id` and `source_slug` stay protected. The sculpt page follows a revert that changes the slug (`reverted` carries the written fields).
- **Colorway stem**: _Stem_ in `app/components/artisan/modal/ColorwayForm.vue` is a multi-select over `artisanStems` (`app/utils/schemas/artisan.ts`: MX, TMX, Alps, Topre, Choc; `stem` is plain `text[]`, not an enum), plus any saved value outside that list so it can be removed; no custom values. An empty selection is saved as `null`. `stem` is one of the Google Doc-managed fields, so editing it adds it to `overridden_fields` (fields are compared with `isEqual`, so arrays count only when their values change).
- **Wishlist Image builder** (`/artisan/wishlist`, all devices; `app/components/artisan/wishlist/`): `ArtisanWishlistPreview` shows an editable `ArtisanWishlistSheet` (two compact columns on phones, drag after a 200 ms press on touch) and captures a second, static sheet through `SharedSnapshot` at `wishlistColumns`/`wishlistGridWidth` (`app/utils/wishlist.ts`). A sheet opens with the wordmark beside the contacts (Discord, Reddit, QQ as transparent badges in their brand colors), then one section per list with items (Want, then Have on a trading list): a heading with a colored bar (info for Want, warning for Have or a selling list) and, beside the sections for sale, the seller's terms when set (_Shipping Included_, _PayPal F&F Only, No Buyer Protection_), over an `ArtisanWishlistGrid` (each its own drag group) of `ArtisanWishlistItem`s. The footer holds the date and `AppWordmark domain`. In the editor the sheet is framed as a page. An item is the square photo with the colorway name and its sculpt and maker under it (`GET /api/users/:id/collection-items` embeds both names); over the photo sit a small price tag (_Offer_ or _Ask_), a _Top Priority_ badge (only the star on phones), a _Found_ or _Sold_ stamp on a greyed photo when it is no longer listed, and in the editor the Top Priority and Remove buttons, which do not start a drag. _Save & Share_ opens `ArtisanWishlistShareModal`: an Image tab (renders on open; Copy Image and Download, plus Share Image on phones with Web Share) and a Text tab (`wishlistText`, Markdown or plain, format in the `wishlist-text-format` cookie). Settings are a `USidebar` (slideover below `lg`): Buying / Selling / Trading tabs (text only, since tab icons hide the labels in the narrow sidebar) (switching resets the collections, titles, and terms), then Want (or List) and Have groups with a collection and a title, Layout (columns), Contact, and the seller Terms as switches; empty states open it, so the phone settings button appears only once a collection is picked. The drag tip is dismissed through the `wishlist-drag-hint-seen` cookie.
