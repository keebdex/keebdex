# Leaderboard

Feature reference for Keebdex agents; project-wide rules live in [AGENTS.md](../../AGENTS.md).

Contributor rankings on `/leaderboard` and the home page.

- **Leaderboard** (`/leaderboard`, public, SSR): `GET /api/leaderboard?period=all|month&module=` returns the public board and `GET /api/leaderboard/me` (same query) the caller's own row, loaded in the browser only through `useLeaderboardMe`, from the `leaderboard` / `leaderboard_me` database functions (`20261027000000_leaderboard`), which score published records a user submitted (`submitted_by`; 5 points for a maker, sculpt, profile, keyset, brand, or keyboard, 3 for a colorway, kit, release, or variant) and approved edit suggestions (1), dated by `verified_at`, else `created_at`; staff count like everyone (`submitted_by` defaults to `auth.uid()`, see `docs/agents/submissions.md`). Both return the composite `leaderboard_entry` and expose only name and avatar, from `user_display()` like `revision_actors()` (`toLeaderboardEntry` names a nameless collector once); the board is the top 10 (rank ties share a place). `users.leaderboard_hidden` (the toggle in Account Settings, `userStore.leaderboardHidden`) leaves the board; `me` still ranks the caller. Weights live in the migration and in `LEADERBOARD_POINTS` (`app/utils/leaderboard.ts`); change both together; the navbar's _How Points Work_ button (`LeaderboardPointsGuide`, a popover on hover, or on tap on phones) explains them. The page shows the first three on `LeaderboardPodium` (second, first, third; ties share a medal through `leaderboardMedal(rank)`), then the rest as `LeaderboardRow`s under `LeaderboardHeader`, whose count columns (`LEADERBOARD_COLUMNS`) appear from `md`, with the caller's own row (`me`, highlighted) merged in rank order when they are not on the board (after a gap when ranks are skipped); the module tabs show icons only on phones.
