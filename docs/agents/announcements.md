# Announcements

Feature reference for Keebdex agents; project-wide rules live in [AGENTS.md](../../AGENTS.md).

Admins publish site-wide announcements without a deploy. Each one shows (`display`) as a toast on every page (added once per page load by the layout), as the banner across the top of every page, or neither (`none`), and is always listed in the Announcements tab of `/notifications` (signed-in users). Migrations `20261011000000_announcements` (after the notification migrations) and `20261015000000_announcement_display` (`display`, backfilled from the dropped `show_toast`); `supabase/seed/announcements.sql` holds the announcements that used to be hard-coded toasts and must also run in production.

- **Tables**: `announcements` (`key` primary key, also the toast id and the dismissal key, never changed after creation; `title`, `description`, `icon`, `color`, optional `cta_label` + `cta_url` together, `display` `toast | banner | none` (`ANNOUNCEMENT_DISPLAYS`), `audience` `all | guest | signed_in | mods`, `priority` (higher first), `starts_at`, `ends_at`). Check constraints mirror `app/utils/schemas/announcement.ts`: `cta_url` is `https://` or an internal path (`/x`, not `//x`), no whitespace. `announcement_dismissals (user_id, announcement_key, dismissed_at)` cascades on delete.
- **RLS**: anyone, guests included, reads live announcements (`starts_at <= now() < ends_at`), except `mods`, readable only by `can_manage_any()` (mirrors `canManageAnyAssignment`); admins read all rows and are the only writers. Users read and insert their own dismissals, and only for announcements they can see. RPCs (security invoker): `dismiss_announcement(key)`, `merge_dismissals(keys)` (skips unknown or hidden keys). `unread_count()` stays personal-only.
- **API**: `GET /api/announcements` → `{ data, signedIn, userId, dismissed, toasts }`; guests get `all`/`guest`, signed-in users everything but `guest` (RLS removes `mods` for non-staff). `POST /api/announcements/[key]/dismiss`, `/merge-dismissals` `{ keys }`, `/seen`. Admin: `GET` / `POST /api/admin/announcements`, `POST` / `DELETE /api/admin/announcements/[key]` (update is a patch; unpublish sends `ends_at`). Bodies are validated by `announcementSchema` / `announcementPatchSchema`, which also act as the field whitelist, and constraint errors map to 400/409.
- **Client**: `useAnnouncements()` (shared state; `load()` is latest-wins and every caller resolves with the latest result). Dismissed and read are the same thing. Guests: this device's `dismissed-announcements` localStorage list plus legacy `acknowledged` values (localStorage or cookie) stored under an announcement's key by the old toasts. Signed in: `announcement_dismissals` is the source of truth, plus this device's keys not yet merged for that user (`announcement-dismissals-merged:<uid>`), so clearing the table shows announcements again. Dismissing writes the server when signed in (and the device list, marked as merged) or the device list for guests. `plugins/announcements.client.ts` merges this device's keys once per user on sign-in, then loads announcements (for the sidebar badge) and refreshes them when the tab becomes visible. On mount, the layout (`app/layouts/default.vue`) shows up to `ANNOUNCEMENT_TOAST_LIMIT` (3) toasts by priority plus a "+N more updates" toast (to the Announcements tab, or `/changelog` for guests) when there are more, then the cookie consent. The layout stays mounted across navigation, so they show once per page load, whatever the first page. When the stack expands, announcements sit 8px apart instead of the toaster's 16px (`ANNOUNCEMENT_STACK_CLASSES`, a `translate-y` that adds to the toaster's `transform`, recomputed as toasts land or are dismissed), so they read as one group between the cookie consent and the summary. Announcement toasts (and the summary) hide after the toaster's default duration and come back on the next page load; only the CTA or Dismiss records the dismissal. They have no close button, since closing would look like dismissing. The banner (`bannerItem`) is the highest-priority undismissed `banner` announcement, one at a time, rendered by the layout as a `UBanner` (`announcementBanner`, no `id`, so not UBanner's localStorage) above the page; its close button and CTA dismiss it and the next one takes its place. The `announcement_toasts` preference does not hide it. Toast and banner builders and helpers live in `app/utils/announcements.ts`.
- **Tab**: `/notifications?tab=announcements` lists every live announcement (read ones too), grouped by day like notifications and newest first (priority only orders toasts and banners), with `NotificationAnnouncementItem` on `NotificationRow`: the CTA is the button below. Unread = not dismissed; the tab badge and the sidebar badge count them. Mark as read (hover, unread only) or the CTA dismisses one; Mark all as read dismisses every unread one. Reading is one-way (no Mark as unread). Announcements never mix into the Notifications tab; the All / Unread filter applies to both tabs.
- **Admin**: `/admin/announcements` (Management menu) lists scheduled, live, and ended announcements with Preview Toast, Edit (`ModalAnnouncementForm`, with a _Show As_ radio card group from `ANNOUNCEMENT_DISPLAY_OPTIONS`, labelled previews: the banner first for banners, then the Announcements tab row every announcement gets; Preview Toast only for toasts), Unpublish, and Delete.
