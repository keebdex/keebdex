# Cloudflare Workers

Feature reference for Keebdex agents; project-wide rules live in [AGENTS.md](../../AGENTS.md).

Production runs on Cloudflare Workers (Workers Builds, Paid plan: CPU time is billed per request and capped by `limits.cpu_ms` in `wrangler.jsonc`; 128 MB of memory; Error 1102 when exceeded), so keep Worker work small:

- `routeRules` in `nuxt.config.ts`: `/about`, `/features`, `/changelog`, `/privacy`, and `/why-choose-keebdex` are prerendered (served as static files); private pages and tools (`/account/**`, `/admin/**`, `/notifications`, `/recent-changes`, `/collection`, submission pages, `/artisan/wishlist`, `/artisan/marketplace`, `/artisan/search`) are `ssr: false`, and the private ones among them (`privatePage`) are also `noindex`. Public catalog pages keep SSR. Do not cache rendered HTML: it depends on the theme and color-mode cookies and the device. Add new private or list-heavy pages to the `ssr: false` group.
- `/sitemap.xml` comes from `@nuxtjs/sitemap` (`sitemap` in `nuxt.config.ts`): static pages are listed from `app/pages` unless their route rule sets `sitemap: false`, and `server/api/__sitemap__/urls.get.ts` adds every published maker, sculpt, profile, keyset, brand, and keyboard (children only under a published parent), selecting keys only. Both the sitemap and the source are cached for an hour per isolate. Add new dynamic page types to the source; `/__sitemap__/debug.json` (dev) lists what each source returned.
- Environment variables are listed in `.env.example`, each marked build or runtime. `nuxt.config.ts` runs only at build time, so `process.env` there bakes values into the bundle: never read secrets that way. Runtime values use `NUXT_` names matching `runtimeConfig` (`NUXT_CLOUDFLARE_*` for image uploads, `NUXT_APP_SECRET` for OG image URLs) and are set as Worker Secrets. The Cloudflare Images account hash (`runtimeConfig.public.cloudflare.accountHash`, not a secret: it is in every image URL) defaults to Keebdex's in `nuxt.config.ts` and is overridden by `NUXT_PUBLIC_CLOUDFLARE_ACCOUNT_HASH`; only resizing uses it, since image uploads take their URL (the `/public` variant) from Cloudflare's response. `NUXT_PUBLIC_SUPABASE_URL`/`_KEY` are needed at build time too (prerendering); a build without them deploys and then answers every request with a 500.
- `nitro.preset` is set to `cloudflare_module` on Cloudflare builds (`NITRO_PRESET` overrides it). Nitro would detect Workers Builds on its own, but nuxt-og-image reads the preset from the config and otherwise builds for `node-server`: OG images then fetch their fonts (`/_nuxt/fonts/*.woff2`) through Nitro, which serves no public assets on Workers, instead of the `ASSETS` binding, and fall back to a default font. Check OG image font changes on a Cloudflare build (`wrangler dev` on `.output/server/wrangler.json`), since the dev server loads fonts another way.
- Workers Builds deploys the `wrangler.json` that Nitro generates, replacing the Worker's dashboard settings. Bindings and settings (the `keebdex.org` custom domain, the D1 `DB` binding, also declared under `previews` so preview deployments get it, observability, placement, CPU limit, `keep_vars`) therefore live in the root `wrangler.jsonc`, which Nitro merges in; only Secrets survive from the dashboard.
- Keep SSR payloads small: trim with `pick`/`transform` in `useAsyncData` (e.g. `useKeysetProfiles`, the maker list) or select fewer columns on the server.
- Icons: `@nuxt/icon` bundles every icon named in `app/` and `content/` (`icon.clientBundle.scan`, shared by SSR) and loads any other (e.g. announcement icons from the database) from the Iconify API (`provider: 'iconify'`). Keep that provider rather than the server one: on Cloudflare the server provider downloads and parses whole collections (solar is 11.7 MB) inside every new Worker isolate.
- `flag-icons` CSS is imported only by `MakerForm.vue` and `BrandForm.vue`, and its SVGs are emitted as files (`vite.build.assetsInlineLimit`); imported globally it added ~420 kB of inline CSS to every SSR response.
- Security headers (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, CSP) come from `routeRules['/**'].headers` in `nuxt.config.ts` (`securityHeaders`). The Cloudflare preset also writes every route rule header into `.output/public/_headers`, which is how the prerendered pages (served by Workers static assets, not the Worker) get them: do not add a `public/_headers` with the same headers, since Workers would join the duplicates (`DENY, DENY`). They merge with the per-route rules (`privatePage` keeps its `x-robots-tag`). HSTS is not set in the repo: it comes from the Cloudflare zone settings.
- The CSP is `Content-Security-Policy-Report-Only` for now: `script-src` needs `'unsafe-inline'` (inline theme script, Nuxt payload and importmap; prerendered and `ssr:false` pages have no per-request nonce) and `style-src` too, so it mainly limits where scripts load from and where data is sent. Add any new third-party origin (script, API, websocket) to its list in `nuxt.config.ts`. The build adds the origin of `NUXT_PUBLIC_SUPABASE_URL` (and its `ws(s)` form) next to `*.supabase.co`. Violations are posted to `server/api/csp-report.post.ts`, which answers 204 and logs one `csp-violation` line (directive, blocked origin, page path; bodies over 8 KB get 413) to the Worker logs. Switch to the enforcing `Content-Security-Policy` once the reports are quiet.
